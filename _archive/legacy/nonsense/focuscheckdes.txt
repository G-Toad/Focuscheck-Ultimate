● COMPREHENSIVE FOCUSCHECK CODEBASE ANALYSIS & DOCUMENTATION

  EXECUTIVE SUMMARY

  FocusCheck is a sophisticated, Windows-focused productivity application designed to help users maintain focus and track time management through
  periodic prompts and behavioral interventions. The application employs a unique psychological approach combining periodic check-ins, progressive
  escalation mechanics, task management, and anti-habit patterns to prevent mindless responses.

  Primary Purpose: Interrupt the user at configurable intervals to ask: "What are you doing right now?" forcing conscious reflection on whether time is
  being spent productively or wastefully.

  ---
  ARCHITECTURE OVERVIEW

  System Design Philosophy

  FocusCheck follows a modular, defensive architecture with:
  - Graceful degradation: Every feature has fallbacks
  - Cross-platform considerations: Primarily Windows but structured for potential portability
  - Fail-safe defaults: Conservative settings to prevent overwhelming users
  - Extensive error handling: Try-except blocks at every level to ensure robustness

  Core Architectural Patterns

  1. Mixin-based UI composition: Dialog classes composed of specialized mixins
  2. Settings-driven behavior: Nearly all behavior configurable via JSON settings
  3. Event-driven Windows integration: Hooks into OS-level events (lock, sleep, display changes)
  4. Database persistence: SQLite for task tracking, CSV for logging
  5. Single-instance enforcement: Prevents multiple copies running simultaneously

  _schedule_next(delay_ms)

  Lines: 300-316

  Purpose: Schedules the next prompt dialog

  Behavior:
  - Cancels any existing scheduled prompt

  _maybe_show_prompt()

  Lines: 346-393

  Purpose: Conditionally shows a prompt if not paused

  Decision Tree:
  1. Reload settings (line 347): Always fresh settings for each prompt
  2. Check global pause (lines 349-355): If manually paused via tray, reschedule and skip
  3. Prevent duplicates (lines 357-363): If a prompt already open, defer 1.5 seconds
  4. Check PauseGuard (lines 365-368): Skip if system idle/locked/lid closed
  5. Show PromptDialog (lines 370-393): Creates dialog and uses non-blocking check loop

  Non-blocking Wait Pattern (lines 379-393):
  - Instead of wait_window() (which blocks and can cause GIL issues with pystray threading), uses a polling check every 100ms
  - Allows pystray thread to remain responsive during dialog display

  Purpose: Handles system wake/unlock

  Behavior:

  Progressive Escalation Levels:

  Level 0: Normal (calm, neutral)
  - Standard button colors
  - No visual distraction

  Level 1: Gentle nudge
  - Pulse effect: Buttons scale ±5 pixels
  - Arrow emojis appear: "←" and "→"
  - Background pulse: Subtle breathing effect

  Level 2: Moderate urgency
  - Shake effect: Rapid horizontal position changes (±3px)
  - Faster pulse
  - More prominent arrows

  Level 3: High urgency
  - Rapid shake (±5px)
  - Rapid pulse
  - Button jiggle: Individual button position randomization
  - Red background flashing

  Overdrive (Level 10): Extreme measures
  - Flash background: Rapid red/black cycling
  - Continuous shake loop
  - Button jiggling intensifies

  Overdrive Stage 4 (after overdrive_stage4_after_seconds from stage 3 start):
  - Ultra-fast flashing: 60ms flash cycle (default)
  - Purpose: Impossible to ignore, creates urgency

  Overdrive Stage 5 (after overdrive_stage5_after_seconds from stage 4 start):
  - Multi-monitor dim/blackout
  - Two engines:
    a. Overlay engine (default): Native Windows click-through overlays on each monitor
    b. Gamma engine: Hardware gamma ramp manipulation (more invasive)
  - Pulsing dim: Alpha oscillates to maintain attention
  - Optional slow dim: One-way fade to black over N seconds
  - Optional hold: Final black screen after timer expires

  IF pause_when_inactive_or_lid_closed disabled: return False

  IF pause_on_lid_closed AND lid closed: return True
  IF Windows:
      IF pause_on_lock AND locked: return True
      IF pause_on_sleep AND sleeping: return True
  return False

  EXECUTION FLOW

  Typical Session Timeline

  1. 00:00 - Launch
    - User runs Start FocusCheck.cmd or main.py
    - App class initializes, loads settings
    - System tray icon appears
    - Windows event hooks installed
    - First prompt scheduled for 2 seconds (line 245: "quick first pop to prove it works")
  2. 00:02 - First Prompt
    - PromptDialog appears centered on active monitor
    - User sees: "Studying" and "Wasting time" buttons (randomized order)
    - Time info label shows elapsed time (if enabled)
    - Task panel shows active task (if any)
  3. 00:02-00:17 - User Delay (Intensification)
    - 00:17 (interval + 15s): Intensification begins
        - Level 1: Gentle pulse, arrows appear
      - Level 2: Shake effect added
      - Level 3: Rapid shake, button jiggle, red flashing
  4. 00:02-01:02 - User Still Delaying (Overdrive)
    - 01:02 (interval + 60s): Overdrive begins
        - Continuous background flash
      - Shake loop
      - Intensified button jiggling
      - Audio alarm starts (if enabled)
  5. 01:02-01:14 - Overdrive Stage 4
    - 01:14 (overdrive + 12s): Stage 4 begins
        - Ultra-fast red flashing (60ms cycle)
      - Maximum visual urgency
  6. 01:14-02:14 - Overdrive Stage 5
    - 02:14 (stage 4 + 60s): Stage 5 begins
        - Multi-monitor overlays appear on all screens
      - Gradual dim to 92% black (default)
      - Pulsing alpha to maintain awareness
      - Optional: Slow fade to solid black
      - Optional: Hold at black after N seconds
  7. User Responds - "Studying"
    - Hold button for 800ms (default)
    - FocusPromptDialog appears
    - User types what they're studying
    - Challenge possibility (30% chance): Reflection prompt instead
    - Spam detection validates response
    - Logged to focus_events table and CSV
  8. Next Cycle
    - Scheduled for 60 seconds (default interval_seconds)
    - Repeat from step 2

  Pause Scenarios

  Scenario 1: User Locks Windows (Win+L)
  - WindowsWakeWatcher receives WM_WTSSESSION_CHANGE with WTS_SESSION_LOCK
  - Calls App._on_pause_event("lock")
  - PauseGuard._locked set to True
  - _maybe_show_prompt checks PauseGuard.should_pause(), returns True
  - Next prompt rescheduled for pause_poll_interval_seconds (5s default)
  - On unlock: WTS_SESSION_UNLOCK event → _on_resume_event() → immediate prompt scheduled

  Scenario 2: System Sleep
  - WM_POWERBROADCAST with PBT_APMSUSPEND received
  - PauseGuard._sleeping set to True
  - Prompts paused
  - On wake: PBT_APMRESUMESUSPEND event → immediate prompt

  Scenario 3: Laptop Lid Closed
  - PauseGuard._looks_lid_closed_*() methods detect lid state
  - Prompts paused while lid closed
  - Resume: Next heartbeat check detects lid open, resumes

  Scenario 4: Manual Tray Pause
  - User right-clicks tray, selects "Stop reminders"
  - App._tray_pause() sets settings["paused"] = True
  - Saves settings to disk
  - Prompts poll every 5 seconds but skip showing
  - Resume: "Start reminders" sets paused = False

  Spam Detection System

  Purpose: Prevent low-effort responses to reflection prompts

  Detection Strategies:

  1. Gibberish Detection:
    - Vowel ratio check: Rejects text with too few/many vowels (0.15-0.75)
    - Unique character ratio: Requires diversity (0.3 minimum)
    - Example rejected: "asdfghjkl" (no vowels, keyboard pattern)
  2. Repetition Check:
    - Consecutive chars: Max 3 same characters (e.g., "aaaa" flagged)
    - Pattern repetition: Max 4 repetitions (e.g., "asdfasdfasdfasdf" flagged)
  3. Spacing Check:
    - Minimum length for spaces: Text ≥20 chars must have spaces
    - Prevents "studyingstudyingstudying"
  4. Keyboard Pattern Detection:
    - Detects sequences like "qwerty", "asdf", "zxcv"
    - Minimum sequence: 5 chars (configurable)
  5. Dictionary Validation:
    - Real word ratio: Requires 50% real words
    - Minimum word length: 2 characters
    - Uses English word list (implied from implementation)
  6. Timing Validation:
    - Minimum time to submit: 2 seconds (prevents instant spam)
    - Flag threshold: Warns if under 1 second
  7. Banned Words: Rejects responses containing "idk", "dunno", "meh", "whatever"
  8. Vague Words: Flags "stuff", "things", "something", "nothing"

  User Experience:
  - Error dialog shows specific issue: "Response appears to be gibberish"
  - User can retry with improved response
  - No bypass option (forces quality response)

  Challenge System

  Purpose: Force deeper reflection via targeted prompts

  Architecture:
  - challenge_system.py: Challenge selection and validation
  - Context-aware: Different challenges for "studying" vs "wasting"
  - Frequency-controlled: challenge_studying_frequency, challenge_wasting_frequency

  Studying Challenges (4 types):
  1. Learning Specificity: "What specific skill or knowledge are you developing right now?"
  2. Goal Connection: "How does this connect to your larger goals?"
  3. Will Commitment: "Why is it important that you do this now?"
  4. Output Expectation: "What do you expect to produce or understand after this session?"

  Wasting Challenges (7 types):

  3. Because Reasoning: "Why are you choosing to waste time right now?"
  4. Hour Projection: "If you continue this for an hour, what will you have lost?"
  5. Tomorrow Regret: "Will you regret this tomorrow?"
  6. Fear Acknowledgment: "What are you afraid might happen if you do what you should instead?"
  7. Lying Confrontation: "Are you lying to yourself? If so, about what?"

  Validation Requirements:
  - Minimum words: 3 (default)
  - Minimum characters: 10 (default)
  - No bypass: challenge_allow_skip controls whether user can cancel

  Hints (optional):

  TROUBLESHOOTING GUIDE

  Issue: Tray Icon Not Appearing

  Diagnosis:
  1. Check startup logs for "tray start succeeded" or "tray start failed"
  2. Look for pystray import errors: "pystray import FAILED"

  Solutions:
  - Install pystray: pip install pystray pillow
  - Check Windows 11 overflow: Click ^ in taskbar to see hidden icons
  - Enable native tray: If pystray fails, native tray auto-enables
  - Verify icon file: Ensure imageedit_5_9158249849.png exists

  Issue: Prompts Not Appearing

  Diagnosis:
  1. Check settings: paused may be True
  2. Check pause guard: pause_on_idle, pause_on_lid_closed, pause_on_lock
  3. Check force_always_on: Should be True to ignore pause mechanisms
  4. Review logs: "paused; deferring prompt"

  Solutions:
  - Right-click tray → "Start reminders"
  - Set force_always_on: true in settings
  - Disable unwanted pause mechanisms

  Issue: Audio Not Playing

  Diagnosis:
  1. Check platform: Only works on Windows
  2. Check settings: audio_alerts_enabled must be True
  3. Check logs: "Audio not available: winsound import failed"

  Solutions:
  - Ensure Windows platform
  - Verify winsound available (standard on Windows Python)
  - Check audio device: Is sound card working? Are speakers/headphones connected?

  Issue: Database Locked Errors

  Diagnosis:
  1. Another instance running: Check Task Manager for multiple python.exe
  2. File permissions: Can't write to %APPDATA%

  Solutions:
  - Kill duplicate instances: Task Manager → End Task
  - Check file permissions: Ensure user can write to %APPDATA%/FocusCheck
  - Check disk space: Ensure drive not full

  Issue: Overdrive Stage 5 Not Working

  Diagnosis:
  1. Check settings: overdrive_stage5_enabled must be True
  2. Check engine: overdrive_stage5_engine set to "overlay" or "gamma"
  3. Check logs: "Stage 5 overlays failed"

  Solutions:
  - Enable in settings
  - Try switching engine: "overlay" is more compatible
  - Check multi-monitor setup: Some configurations may fail
  - Verify Windows permissions: UAC may block overlay creation

  FINAL SUMMARY

● FocusCheck is a psychologically-engineered productivity intervention system that operates on the principle of forced conscious awareness. Rather than
  passive time tracking, it actively interrupts users at regular intervals, demanding honest self-assessment of their current activity.

  Key Distinguishing Features:

  1. Progressive Escalation: Unlike simple reminders, FocusCheck escalates through 5 distinct urgency levels, from gentle nudges to screen-dimming
  overlays, making it nearly impossible to ignore.
  2. Anti-Habit Design: Randomized button placement, press-and-hold requirements, and challenge prompts prevent users from developing mindless response
  patterns.
  3. Deep Windows Integration: Hooks into OS-level events (lock, sleep, power, display changes) for intelligent pause/resume behavior.
  4. Comprehensive Data Tracking: SQLite database + CSV logs capture not just when prompts occurred, but response latency, intensity reached, user
  reflections, and task correlation.
  5. Defensive Architecture: Every subsystem has fallbacks (dual tray systems, multiple dimming engines, optional features) ensuring the app continues
  functioning even when individual components fail.
  6. Behavioral Psychology: Challenge system forces metacognitive reflection ("What are you afraid might happen if you do what you should?"), spam
  detection prevents low-effort responses, and task deadlines create accountability pressure.

  Technical Sophistication:

  - Mixin-based UI composition for clean separation of concerns
  - Atomic file operations with fsync for settings durability
  - WAL-mode SQLite for concurrent access
  - Thread-safe CSV logging with per-file locks
  - Native Windows overlays with click-through transparency
  - GDI+ integration for PNG-to-HICON conversion
  - Event-driven Windows hooks via WndProc subclassing

  This codebase represents a complete, production-ready productivity application with enterprise-grade error handling, extensive configurability, and
  thoughtful UX design aimed at behavioral change rather than mere tracking.
